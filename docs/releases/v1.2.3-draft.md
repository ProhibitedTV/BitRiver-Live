# BitRiver Live v1.2.3 draft release notes

Status: draft for the first credible public release of the current `v1.2.3` line.

## Summary

BitRiver Live packages the core pieces of a self-hosted live-streaming stack into one repository and one deployment contract:

- Go API and admin control plane
- Next.js viewer
- SRS ingest
- OvenMediaEngine playback
- FFmpeg-based transcoding
- Postgres and Redis
- Compose-based deployment assets, installers, and release automation

This release focuses on making that stack approachable and trustworthy for public adopters: cleaner repo hygiene, clearer onboarding, explicit support boundaries, and a more complete contribution and release surface.

## What operators get

- A documented single-host deployment baseline centered on `deploy/docker-compose.yml`
- Quickstart and smoke-test flows from the same source tree
- A production golden-path gate that publishes deterministic 1080p RTMP,
  decodes OME and transcoder playback, exercises chat/moderation and VOD, checks
  aggregate health, scans its evidence, and tears down
- Source-free Linux launcher archives and amd64/arm64 `.deb`/`.rpm` packages assembled from one canonical asset manifest
- An Ubuntu systemd host manager that stages the Compose stack under `/opt/bitriver-live`, keeps configuration/data separate, and never activates sample credentials
- Release artifacts for binaries, launcher bundles, viewer bundle, and version-matched container images, including the OME config helper
- Supporting runbooks for security, upgrades, monitoring, and production release execution

## Known limits

- The supported baseline is still operator-managed single-host deployment.
- HA or multi-host guarantees are not part of this release.
- Kubernetes is not the primary deployment path in this repository.
- Operators still own host hardening, secret rotation, backups, and capacity planning.
- Ubuntu Server 24.04 LTS on amd64 is the production installation target. Debian 12, RPM hosts, arm64, and XOA reboot recovery remain provisional until tagged clean-host evidence is attached.
- Source-built canonical Compose now has automated real RTMP, OME/transcoder
  decode, chat/moderation, VOD, and aggregate-health proof. Pull-only tagged
  artifacts, clean-host Ubuntu installation, reboot recovery, and browser
  recovery/quality behavior still require their own evidence.

## Recommended upgrade / rollout notes

1. Validate your target environment with `deploy/check-env.sh`.
2. Follow [`docs/production-release.md`](../production-release.md) before tagging or rolling out.
3. Confirm release notes, checksums, image digests, and the changelog agree on the final tag.
4. Run `scripts/test-production-golden-path.sh --stack running --client docker`
   against the deliberately prepared release-candidate installation and retain
   its sanitized JSON report.
5. Install only the published artifacts on a clean Ubuntu 24.04 amd64 VM, reboot it, and record authenticated OME plus real ingest/playback evidence before announcing production readiness.
