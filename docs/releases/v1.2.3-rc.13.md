## Install entry points

- Windows Docker Desktop evaluation: clone the repository and run
  `.\scripts\verify-windows-docker.ps1 -Start` with Linux containers.
- Ubuntu Server 24.04 amd64: download
  `bitriver-live_v1.2.3-rc.13_amd64.deb` or
  `bitriver-launcher-linux-amd64.tar.gz`, `CHECKSUMS.txt`, `release-set.json`,
  and `release-set.sigstore.json`; then follow
  [`../installing-on-ubuntu.md`](../installing-on-ubuntu.md).
- Source evaluation on Linux/macOS/Git Bash: follow
  [`../quickstart.md`](../quickstart.md).

Do not mix artifacts, signatures, checksums, tags, or digests from different
releases. Verify the signed root before installing a selected payload.

## Known limits before stable promotion

- Ubuntu Server 24.04 amd64 is the production installation target. Debian,
  RPM hosts, and arm64 remain provisional production hosts.
- Clean installation and reboot on the intended XCP-ng/XOA VM still require
  evidence from that actual host.
- Nginx Proxy Manager TLS/WebSocket/browser/media routing plus router/firewall/
  NAT behavior still require the operator's real topology.
- Authenticated OME, real ingest/playback after reboot, and repeated failure/
  recovery must be repeated on the target host even though the release image
  gate passed those paths on its hosted runner.
- Backup/restore, populated upgrade/rollback, capacity, resilience, SLO,
  security, and browser-compatibility gates remain open and must bind to this
  exact release-set hash before stable promotion.

## Upgrade and rollback

Back up `/etc/bitriver-live`, Postgres, and `/var/lib/bitriver-live` before an
upgrade. Keep the previous package and its exact image digests available for
rollback. Follow [`../upgrades.md`](../upgrades.md) and
[`../production-release.md`](../production-release.md); never move or reuse a
published tag.
