# SPEC

## User goals
- Make repo work planning explicit and repeatable for contributors and agents.
- Ensure work can be executed without relying on chat context.
- Keep planning and execution lightweight.

## Success criteria
- A contributor can follow `SPEC.md` → `PLAN.md` → `TASKS.md` in order.
- `PLAN.md` is updated during initial read-only analysis before implementation.
- `TASKS.md` lists small, reviewable tasks in execution order with status + acceptance criteria.
- After each completed task, the assignee runs relevant tests/checks and records status in `TASKS.md`.
- Workflow docs remain short working artifacts.
